# Сочетания клавиш

Leader — пробел (`<Space>`), LocalLeader — обратная косая черта (`\`, для Octo).
`n` — normal, `x` — visual, `o` — ожидание оператора, `i` — insert, `c` — командная строка,
`s` — выделенное поле сниппета, `t` — terminal. `<CR>` — Enter, `<C-…>` — Ctrl, `<S-…>` — Shift,
`<A-…>` / `<M-…>` — Alt/Option. Регистр букв имеет значение.

Здесь перечислены **все личные бинды** из `lua/config/keymaps.lua`, а ниже — автодополнение и
основные встроенные команды. Полный список локальных биндов установленных плагинов:
[PLUGIN_KEYMAPS.md](docs/PLUGIN_KEYMAPS.md). Локальные бинды перекрывают глобальные в окне плагина:
например, `<C-p>` в Oil открывает preview, в поиске выбирает предыдущий результат, а в обычном буфере ищет файл.

В Neovim: `<Space>fk` ищет текущие бинды; после Leader Which-key показывает группы.
Для проверки конкретного сочетания: `:verbose nmap <C-p>` или `:verbose imap <Tab>`.

## Что изменилось

| Раньше | Теперь | Причина |
| --- | --- | --- |
| Бинды Runic и `<Space>cf…` | Удалены | Запуск задач остаётся в Overseer и Gradle; группа `r` содержит `rr`, `rj`, `ra` |
| `<C-p>` и `<Space>ff` | Только `<C-p>` | Убран дубль поиска файлов |
| `j` / `k` | По экранным строкам в `n/x` | Удобнее при включённом wrap; `5j` / `5k` и движения после оператора считают строки файла |
| `n` / `N` | Поиск с центрированием и раскрытием складок | Совпадение видно после перехода |
| `gd` / `gD` | Определение / объявление через LSP | Переходы к коду через подключённый сервер |
| `<C-l>` — перерисовка | Переход в окно справа | Единая схема `<C-h/j/k/l>`; перерисовка остаётся на `:redraw!`, очистка поиска — `:nohlsearch` |
| `<C-d>` / `<C-u>` с `zz` в `n/x/o` | Центрирование только в `n` | В visual и operator-pending восстановлено стандартное поведение; `zz` там не центрировал экран корректно |
| `<Space>bf` только в `n` | В `n/x`, асинхронно | Можно форматировать выделение и продолжать работу |
| `<Tab>` / `<S-Tab>` от Tabout | Blink → сниппет → Tabout | Поля сниппетов имеют приоритет; выход из скобок и кавычек сохранён |
| `<Space>ql` с описанием «Select» | Тот же бинд, описание «Load latest» | Он читает локальную/последнюю сессию; выбор сессии остаётся на `qp` |
| — | `<Space>fk`, `<Space>-`, `<Space>xx`, `<Space>xq` | Поиск биндов, Oil, диагностика и quickfix в Trouble |

Остальные личные сочетания сохранены. Встроенные переходы Neovim не назначаются повторно.
`[c` / `]c` переходят по изменениям Gitsigns, в diff сохраняют стандартное движение;
в окнах Octo локальные бинды этих клавиш переходят по комментариям.

В терминале `<C-h/j/k/l>` переключают окна и выходят из режима ввода.
Чтобы снова вводить команды, нажать `i`; встроенное `<C-\><C-n>` только выходит в normal.

## Автодополнение Blink

Используется preset `enter`. Если меню закрыто, клавиши с fallback выполняют обычное действие.

| Клавиши | Режим | Действие |
| --- | --- | --- |
| `<CR>` | `i` | Принять выбранное дополнение; без выбора — обычный Enter |
| `<C-Space>` | `i` | Показать дополнения / показать или скрыть документацию |
| `<C-e>` | `i` | Отменить дополнение |
| `<C-n>`, `<Down>` | `i` | Следующее дополнение |
| `<C-p>`, `<Up>` | `i` | Предыдущее дополнение |
| `<C-b>`, `<C-f>` | `i` | Прокрутить документацию вверх / вниз |
| `<C-k>` | `i` | Показать или скрыть сигнатуру функции |
| `<Tab>`, `<S-Tab>` | `i` | Следующее / предыдущее поле сниппета; иначе выход из скобок/кавычек через Tabout |
| `<Tab>`, `<S-Tab>` | `s` | Следующее / предыдущее поле встроенного сниппета Neovim |
| `<Tab>`, `<S-Tab>` | `c` | Показать дополнения, вставить единственный вариант или выбрать следующий / предыдущий |
| `<C-Space>` | `c` | Показать дополнения |
| `<C-n>`, `<Right>` / `<C-p>`, `<Left>` | `c` | Следующий / предыдущий вариант |
| `<C-y>` | `c` | Выбрать и принять дополнение |
| `<C-e>` | `c` | Отменить дополнение |
| `<End>` | `c` | Скрыть меню |

`Tabout` требует Treesitter-парсер для текущего языка. `:TaboutToggle` включает и выключает выход из скобок.

## Встроенные LSP и диагностика Neovim 0.12

Для действий LSP нужен подключённый сервер с поддержкой соответствующего запроса.

| Клавиши | Режим | Действие |
| --- | --- | --- |
| `K` | `n` | Документация символа, если сервер поддерживает hover |
| `grn` | `n` | Переименовать символ |
| `gra` | `n/x` | Code action |
| `grr` | `n` | Ссылки на символ |
| `gri` | `n` | Реализации |
| `grt` | `n` | Определение типа |
| `grx` | `n` | Выполнить code lens |
| `gO` | `n` | Символы текущего документа |
| `<C-s>` | `i/s` | Сигнатура функции |
| `[d`, `]d` | `n` | Предыдущая / следующая диагностика |
| `[D`, `]D` | `n` | Первая / последняя диагностика |
| `<C-w>d`, `<C-w><C-d>` | `n` | Диагностика под курсором в плавающем окне |
| `[q`, `]q`, `[Q`, `]Q` | `n` | Предыдущий / следующий / первый / последний элемент quickfix |
| `gcc` | `n` | Закомментировать текущую строку |
| `gc` + движение / `gc` | `n/x` | Закомментировать область или выделение |

Личные `gd` / `gD` используют LSP (см. таблицу выше). Встроенные `grr`, `gri`, `grt` и `gO`
сохранены, дополнительные алиасы для тех же действий не создаются.

## Встроенное передвижение

Эти сочетания уже доступны в Neovim 0.12 и не добавлены в конфиг повторно.

| Клавиши | Режим | Действие |
| --- | --- | --- |
| `[b`, `]b`, `[B`, `]B` | `n` | Предыдущий / следующий / первый / последний буфер |
| `<C-^>` | `n` | Вернуться к альтернативному буферу |
| `gt`, `gT`, `3gt` | `n` | Следующая / предыдущая / третья вкладка |
| `<C-o>`, `<C-i>` | `n` | Назад / вперёд по истории переходов |
| `g;`, `g,` | `n` | Предыдущее / следующее место изменения |
| `m{буква}`, `'{буква}`, `` `{буква} `` | `n` | Поставить метку / перейти к строке / точной позиции; заглавные метки работают между файлами |
| `gf`, `<C-w>f` | `n` | Открыть файл под курсором / открыть в новом окне |
| `gg`, `G`, `42G` | `n/x/o` | Начало / конец файла / строка 42 |
| `0`, `^`, `$`, `g_` | `n/x/o` | Начало строки / первый непробельный / конец / последний непробельный символ |
| `w`, `b`, `e`, `ge` | `n/x/o` | Начало следующего / предыдущего слова, конец следующего / предыдущего слова |
| `{`, `}` | `n/x/o` | Предыдущий / следующий абзац |
| `H`, `M`, `L` | `n/x/o` | Верх / середина / низ видимой области |
| `<C-w>p` | `n` | Вернуться к предыдущему окну |
| `<C-w>v`, `<C-w>s` | `n` | Создать вертикальное / горизонтальное окно |
| `[z`, `]z`, `zj`, `zk` | `n` | Начало / конец текущей складки, следующая / предыдущая складка |

Сохранённые бинды запуска: `<Space>rj` выбирает задачу Overseer, `<Space>rr` открывает список,
`<Space>ra` выбирает действие (в том числе restart), `<Space>Gg` / `<Space>Gf` открывают Gradle / избранное.
Произвольная команда запускается через `:OverseerShell`; автоматический запуск файла и Codeforces убраны вместе с Runic.

## Обновление таблицы

После изменения `lua/config/keymaps.lua` выполнить из папки конфига:

```sh
nvim --clean --headless -l scripts/generate-keymaps.lua
```

Команда обновляет личные бинды между маркерами. Описания автодополнения и снимок плагинных биндов
относятся к версиям из `nvim-pack-lock.json`; после обновления плагинов их нужно сверить с `g?` / `?` и `:help`.
